# lazarusWeb: What Is the Generated Service Called?

> Service (daemon) projects do not require you to type a service name, but **the CLI and the IDE wizard give different results**:
> the CLI derives it from `--name`, while the IDE wizard always produces `LWApp1Service`.
> This document covers the naming rule, how to rename, and the usual operational commands.
>
> Related: `WINDOWS_SERVICE_en.md` (install/start/stop/troubleshooting), `MANUAL_en.md` ("Create a project with the IDE wizard").
> Recorded 2026-11-20 (verified against a real project generated at `C:\3`); updated 2026-11-21 with the CLI/wizard difference.

## 1. Naming rule: two routes, two outcomes

The common rule lives at `src/core/lwnewproject.pas:379`:

```pascal
function LWServiceName(const O: TLWNewProject): string;
begin
  Result := O.Name + 'Service';
end;
```

`LWServiceMapperSource` writes the result into the mapper's `DD.Name`. It is **independent of the widgetset tier**
(GUI and nogui produce the same service name), but depends on **which route generated the project**:

| Route | `O.Name` used | Service name produced |
|---|---|---|
| CLI `tools\lwnew --name=MyApp --service` | the `--name` value (`tools/lwnew.lpr:102`) | `MyAppService` |
| IDE New Project wizard | placeholder `LWApp1` (`lwdsgnregister.pas:128,429,478`) | **always `LWApp1Service`** |

**Wizard pitfall**: the wizard computes `.lpr` and `uMapper.pas` with the placeholder `LWApp1` *before* saving.
Saving the project as a different name (e.g. `MyApp`) does **not** rewrite `DD.Name` in the mapper.
So "the service name follows the project name" is true only for the CLI; with the wizard you must edit the mapper and reinstall yourself.

## 2. Example: `C:\3` (generated by the wizard; project name happens to be `LWApp1`)

| Item | Value | Notes |
|---|---|---|
| Service name (SCM) | `LWApp1Service` | what `sc.exe` / `net start` use |
| Display name (Services console) | `lazarusWeb · LWApp1 Service` | human-facing, with the framework prefix |
| Description | `lazarusWeb server running as a Windows service` | shown on the service properties page |
| exe | `C:\3\LWApp1.exe` | the service name is unrelated to the exe file name |
| Start type | Automatic (boot start) | `DD.WinBindings.StartType := stAuto` |

Lines 29-38 of `C:\3\umapper.pas` are that definition (the template file is named `uMapper.pas`;
the IDE writes file names in lower case when saving a virtual project, hence `umapper.pas` on disk):

```pascal
  DD := TDaemonDef(DaemonDefs.Add);
  DD.DaemonClassName := 'TLWServiceDaemon';
  DD.Name := 'LWApp1Service';
  DD.DisplayName := 'lazarusWeb · LWApp1 Service';
  DD.Description := 'lazarusWeb server running as a Windows service';
  DD.Options := [doAllowStop];
  DD.WinBindings.StartType := stAuto;      { boot start }
  DD.WinBindings.ServiceType := stWin32;
  DD.WinBindings.ErrorSeverity := esIgnore;
  DD.LogStatusReport := False;
```

## 3. Renaming

The service name is **registered with the SCM**, not read from config at runtime, so renaming requires reinstalling:

1. Edit `DD.Name` in the mapper unit (`uMapper.pas` from the CLI, `umapper.pas` from the wizard; line 31 in this `C:\3` copy; edit the next line too if you want a new display name);
2. Recompile;
3. Uninstall the old service, then install the new one:

```bat
LWApp1.exe --uninstall
LWApp1.exe --install
```

Renaming only the exe does nothing — the SCM uses `DD.Name`.

## 4. Common operations

`build.bat` / `build.sh` already end with these three lines:

```bat
C:\3\LWApp1.exe --install        :: run as Administrator
sc.exe start LWApp1Service
C:\3\LWApp1.exe --uninstall      :: uninstall
```

Query status and the actual registration:

```bat
sc.exe query LWApp1Service
sc.exe qc LWApp1Service
```

> In PowerShell, `sc` is an alias for `Set-Content`; always write the full `sc.exe` for service commands.

## 5. A detail: ini file name casing

The source constant is mixed case, `lazarusWeb.ini` (`lwnewproject.pas:75`), and the CLI `lwnew` preserves it.
**The IDE wizard lower-cases file names when saving a virtual project**, hence `lazarusweb.ini` in `C:\3`
(likewise `lwapp1.lpr` / `umapper.pas`).

Windows file systems are case-insensitive, so the runtime lookup for `lazarusWeb.ini` still finds it — **no functional impact**;
if you later copy the project to Linux, rename it to `lazarusWeb.ini`.

Current `C:\3\lazarusweb.ini`:

```ini
; LWApp1 service config (service cwd is often System32; avoid relative paths)
client=alpine
port=8090

; A Windows service has no console, so enable file logging (resolved against the exe directory)
log=LWApp1.log
```

> The fixed name `lazarusWeb.ini` is deliberate: the final project name is not known before saving,
> and a fixed name is the only way to guarantee "correct before anything is written to disk".
> Lookup order: `lwconfig.pas:302-305`
> (`<exe dir>\<exe name>.ini` → `<exe dir>\lazarusWeb.ini` → the same two names in the current directory).
