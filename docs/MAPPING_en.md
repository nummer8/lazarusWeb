# Control / Property Mapping Tables

Aligned with the actual capabilities of the server-side `src/core/lwwriter.pas`, the default rendering layer `src/client/lw-alpine.js`, and
the optional Ext rendering layer `src/client/lw.js`.
The reports from `tools/lwconvert.exe` are based on exactly these tables; measured coverage is in
[`docs/CONTROL_MATRIX_en.md`](CONTROL_MATRIX_en.md) (auto-generated by `tools\build_audit.bat`).

> **Two-layer note**: the default layer is Alpine.js, which renders the `kind` values in the tables below into native HTML/CSS
> (complex controls such as grid/tree/chart have their DOM/SVG built by `lw-alpine.js` itself); the
> `Ext.*` names appearing in the tables refer to the corresponding components of the **optional Ext layer** (enabled only with `--client=ext` + `ext-<version>/`).
> `kind`, write-back properties, and events are identical across both layers; form templates are supported by both layers (desktop `.html` + mobile `.m.html`,
> `lw-tpl-mode:window|flat`, controls keep their design-time absolute coordinates); the mobile breakpoint/pan fallback exists only in the default Alpine layer.

## Legend

- ✅ Full support: serialization + rendering + value write-back + events
- 🔶 Placeholder: a placeholder box is shown in the browser, other controls are unaffected
- ⛔ Creation failure: construction throws an exception under the nogui widgetset
- ➖ Not serialized (non-visual / internal helper controls)

| TPanel | panel | absolute panel (bevel/border preserved) | — |

| TPageControl | tabs | native tabs (Alpine default) / Ext.tab.Panel (optional) | tab switching (active sent down) |
| TTabSheet | tabsheet | panel inside a tab | — |

> Note: `TTabSheet.Visible` is always False in LCL; tab visibility is managed by the PageControl's
> active page, and the client does not use this field.
>
> `TGroupBox` also carries four client insets `cl/ct/cr/cb`: LCL defines its client
> area as "inside the frame plus the caption band" (win32
> `GetLCLClientBoundsOffset`: top `TMHeight+3`, bottom 2, sides 2). So the frame
> line sits on the middle of the caption band, the caption straddles that line,
> and children start at the client origin. These numbers vary with the font, so
> the server derives them from `Width-ClientWidth` / `Height-ClientHeight` instead
> of letting the browser guess (see `docs/NOTES.md` pitfall 193).

In `KindOf`, after `TEdit` there is another `else if C is TCustomEdit`, so
**any control that truly inherits from `TCustomEdit` automatically falls into `edit`**
(TLabeledEdit, custom single-line inputs…), with no need to register each one individually.

Counter-examples: `TFileNameEdit` / `TDateEdit` / `TCalcEdit` / `TDirectoryEdit` /
`TTimeEdit` / `TEditButton` have the inheritance chain in LCL
`TCustomEditButton → TCustomAbstractGroupedEdit → TCustomControl`,
**not** descendants of `TCustomEdit`, so they do not automatically fall into `edit`. Among them, `TDateEdit`/`TTimeEdit`
later got dedicated kinds (`dateedit`/`timeedit`, see the new mappings and pits 55/70 at the end of this document);
the rest remain placeholders (see the 🔶 list at the end).

## File upload / download

| LCL / API | kind | Description |
|---|---|---|
| TLWFileUpload | fileupload | Ext button + hidden `<input type=file>`; `Filter` / `Multiple` / `MaxSizeKB` / `TargetFolder` / `OnUpload` |

Serialized fields (`lwwriter`, kind = `fileupload`):

```
filter / multiple / maxsize / lastfile (ExtractFileName(LastFileName))
files (array of full paths in UploadedFiles)
```

Runtime semantics:

- Click the button → the browser opens the file picker → `multipart/form-data` POST to
  `/lw/api/upload?sid=<session>&id=<control id>`;
- Server `lwupload.LWProcessUpload` writes each file to disk (`f.Stream` preferred, falling back to `f.LocalFileName`), and the filename is sanitized by `LWSafeFileName` (strip paths,
  strip `..`, replace illegal characters);
- Destination directory: `TargetFolder`, otherwise `%TEMP%\lw_uploads\<sid>\<control name>\`;
- After each file succeeds: `U.AddUploadedFile(path)` → session pushes the new component tree →
  `OnUpload(U, path)` (`TLWFileUploadEvent`);
- The upload response has the same format as that event's response; the browser directly calls `applyPayload` to refresh the UI,
  and the button text shows "Uploading N%" during the upload.

Download side (server proactively pushes a file):

| Method | Effect |
|---|---|
| `TLWForm.SendFile(const AFileName: string; const ADownloadName: string = '')` | Registers a one-time token, pushes a `download` command; the browser dynamically creates an `<a download>` and clicks it |
| `TLWForm.SendText(const AText, ADownloadName: string; const AWithBOM: Boolean = False)` | Writes a temp file then forwards to `SendFile`; `AWithBOM=True` adds a UTF-8 BOM (so Excel opens CSV without garbled text) |

- Command shape: `{"type":"download","url":"/lw/download?t=<token>","name":"<download name>"}`;
- Token = first 16 digits of a GUID + a counter, stored in `lwdownload`'s in-memory table, **valid once only**
  (set to empty after `LWDownloadRelease`), a second access returns 404;
- `GET /lw/download?t=<token>` responds with
  `Content-Disposition: attachment; filename="…"; filename*=UTF-8''<percent-encoded>`,
  so Chinese names are correct in all browsers;
- The sweep thread runs `LWDownloadSweep(30)` each round, reclaiming tokens unused for 30 minutes along with their temp files.

For a complete example see `demos/files` (upload + Chinese-name download + CSV export + double-click a list to download).

## Rich content display (lwweb, corresponding to uniGUI's uniHTMLFrame / uniPDFFrame)

| Control | kind | Description |
|---|---|---|
| TLWHTMLFrame | htmlframe | Renders arbitrary HTML in a panel; published `HTML: TStrings`, runtime content changes are incrementally updated by fingerprint in the browser (without rebuilding the panel) |
| TLWPDFFrame | pdfframe | iframe + the browser's built-in PDF viewer; `PDFFile` (server path, via a view token) or `PDFURL` (external address) |

Serialized fields (`lwwriter`):

```
htmlframe: html (HTML.Text sent down as-is)
pdfframe:  url (/lw/view?t=<view token> or external address; empty string if no file)
           file (ExtractFileName(PDFFile))
```

PDF viewing chain:

- `TLWPDFFrame.ViewURL`: the same file reuses the same view token (cached inside the control),
  and each serialization calls `LWDownloadTouch` to renew it — as long as the session lives the token does not expire;
  when changing files, first `RevokeToken` then sign a new token; a url change in the browser swaps the iframe src;
- `GET /lw/view?t=<token>`: `Content-Disposition: inline`, the token is **not released**
  (unlike the one-time download token), so repeated iframe page turns/refreshes all return 200;
- Browser-side rendering: an empty `url` shows a "no file specified" placeholder; when there is a url, an iframe is created.

See the "PDF display" tab of `demos/dbaware` (hand-written PDF syntax at runtime to generate a sample document +
TLWFileUpload uploading a local PDF for display) and the "HTML display" tab (TMemo editing source for live refresh).

## Dialogs (blocking; `lwdlg` reroutes LCL hooks to the browser)

Business code needs no changes; `ShowMessage` / `MessageDlg` / `OpenDialog1.Execute` are written exactly as before.
The implementation replaces four sets of function pointers in `InterfaceBase` plus the WS classes of `TOpenDialog`/`TSaveDialog`:

| LCL entry | Hook | Command kind | Browser rendering | Return value |
|---|---|---|---|---|
| `ShowMessage` / `ShowMessagePos` | `PromptDialogFunction` | `none` | no icon + OK | none |
| `MessageDlg` / `MessageDlgPos` | `PromptDialogFunction` | by `TMsgDlgType`: `info`/`warning`/`error`/`question` | corresponding icon + button group | `mrNone/mrOk/mrCancel/mrYes/mrNo/…` |
| `InputQuery` / `InputBox` | `InputDialogFunction` | `input` | prompt + single line (`PasswordBox` is password) | `Boolean` + `var Value` |
| `QuestionDlg` | `QuestionDialogFunction` | `question` | custom button text | button's `ModalResult` |
| `Application.MessageBox` / `LCLIntf.MessageBox` | `Forms.MessageBoxFunction` | icon determined by `MB_ICON*` | Windows-style buttons | `IDOK/IDCANCEL/IDYES/IDNO/IDABORT/IDRETRY/IDIGNORE/IDCONTINUE` |
| `TOpenDialog.Execute` | `TWSOpenDialog.ShowModal` | `openfile` | select file (multiple allowed) | `FileName` / `Files` = **server path** |
| `TSaveDialog.Execute` | `TWSCommonDialog.ShowModal` | `savefile` | filename input box | `FileName` = path under the session temp directory |

Command shape (`TLWSession.SessionPushCommand`):

```json
{ "type":"dialog", "id":7, "kind":"question", "caption":"确认", "text":"要保存吗？",
  "buttons":[{"id":4,"text":"保存","default":true},{"id":5,"text":"放弃"},{"id":2,"text":"返回"}],
  "input": {"value":"未命名","mask":false} }
```

- Button `id` is LCL's `idButton*` (`Ok=1`, `Cancel=2`, `Help=3`, `Yes=4`, `No=5`,
  `Close=6`, `Abort=7`, `Retry=8`, `Ignore=9`, `All=10`, `YesToAll=11`, `NoToAll=12`,
  `Open=13`, `Save=14`, `Shield=15`, `Continue=16`, `TryAgain=17`),
  and `PromptDialog` internally maps them to `mrYes/mrNo` via `DialogResults[]`;
- Reply: `POST /lw/api/dlg`, body `sid` / `id` / `r` (button id) / `text` (input value);
- Files: `POST /lw/api/dlgfile?sid=&id=`, `multipart/form-data`,
  written to `%TEMP%\lw_uploads\<sid>\pick\` (open) or `...\<sid>\save\` (save);
- The server thread suspends at `TEvent.WaitFor(LW_MODAL_TIMEOUT_MS=180000)` waiting for the reply,
  only one dialog is allowed at a time per session; with no session, all fall back to LCL's original implementation.

For a complete example see `demos/dialogs` (one button for each of the 7 types), regression `tests/t_dialog.py` (36 cases).

| LCL | kind | Browser side | Write-back target | Events |
|---|---|---|---|---|
| TDBGrid | dbgrid | table (row selection highlighted; **multi-level header** see TLWDBGrid below) | click row → `DataSet.RecNo := row+1` | OnCellClick(Column), OnTitleClick(Column) (click the column header, sorting is done in business code) |

| TDBComboBox | dbcombo | combobox | `Field.AsString` | OnChange |
| TDBText | label | read-only text (writer reads `Field.DisplayText` directly) | — (read-only) | — |
| TDBListBox | dblistbox | list box | sends back selected index → `ItemIndex := n` + item text written to field | OnChange |
| TDBRadioGroup | dbradiogroup | FieldSet + Radio group | sends back the item's **Value** → written to field | OnChange |
| TDBLookupComboBox | dblookup | combobox (valueField=key) | sends back the **KeyField value** → written directly to the foreign-key field | OnChange |
| TDBLookupListBox | dblookuplist | list box (sends back key value) | same as above | OnChange |
| TDBImage | dbimage | image (BLOB → PNG data URI) | — (read-only, follows the field live) | — |

Lookup payload sent down: `items` (ListField display values), `keys` (KeyField values),
`key` (current key, read directly from the bound field — `KeyValue` is a DataLink cache and may not be refreshed yet after the dataset is reopened).
On frontend selection, `keys[i]` is sent back, the server writes the key value into the foreign-key field,
and the ListField display follows automatically via DataChange.

Serialization details (`lwwriter.WriteDBGrid`):

- Sends down `cols` (Title.Caption), `fields` (FieldName), `colwidths`,
  `rows` (`Field.DisplayText`), `recno` (current record, used by the browser for highlighting),
  `count`, `state` (browse/edit/insert);
- **When the dataset is in edit/insert mode, `rows` are not sent down** (moving the cursor triggers an automatic Post),
  the browser keeps the previous data, and sending resumes automatically after Post/Cancel;
- If a numeric field has `DisplayFormat` set, thousands separators are stripped before parsing on write-back.

The three hard rules for SQLite + SQLdb (TEXT→ftMemo, sqoAutoApplyUpdates, edit-mode cursor)
are in `docs/NOTES.md` pit 9.

## Common serialized properties

`id / kind / name / cls / x / y / w / h / align / caption / text / enabled /
visible / hint / fg / bg / font(name,size,style,color) / tab(order) / ev(whitelisted events)`
+ per-kind specific fields (cols/colwidths/rowheight/rows/fixedcols/filter/…).

**`acc` (optional, appears only when needed)**: `&X` in a Caption is LCL's accelerator-key marker
(drawn as an underlined X, triggered by Alt+X); the browser parses it by LCL rules by default; only when a control's
`ShowAccelChar` is explicitly turned off (`TPanel` is off by default) is `acc: 0` sent down,
and the frontend displays it literally. If the field is absent, it means parse, so ordinary controls' payload is not a single byte larger.
See NOTES pit 136 for details (including the complete table of "which text is parsed and which is not").

The event whitelist is in `lwbase.IsLWClickEvent`:
OnClick, OnChange, OnEditingDone, OnExit, OnSelect, OnClose, etc.;
method pointers are obtained via RTTI `GetMethodProp` and called directly, so business code needs no registration at all.

node; grouped headers on the frontend do not send back OnTitleClick (a cross-column header has no unique column), leaf headers work as normal.
The lfm must write `TLWDBGrid` (FPC's GetClass recognizes only exact class names, same as TLWDBNavigator).

| `TTimeEdit` (EditBtn) | `timeedit` (text + iso) | `<input type=time>` (Alpine default) / optional Ext.form.field.Time, format H:i:s, ISO sent back |
